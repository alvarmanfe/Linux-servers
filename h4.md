## b)
- First we logged in our server as a root (*ssh root@94.237.8.85*)
- Then we created a new user *alvar* with *sudo adduser alvar*
- We set a strong password and filled basic user info (in this case we just skipped most of it)
- We granted admin priviledges to *alvar*
  - sudo -> can run administrative commands with sudo
  - adm -> can read system logs
  Now my user *alvar* can fully administer the system without using root.
- Inspected root's home and SSH configuration
  - listed root's files with *ls -a -F* and viewed root's SSH public keys *ls .ssh > cat .ssh/authorized_keys*.
- Copied root's SSH keys to the new user with *cp -r .ssh /home/alvar/* (the entire SSH directory). That allow me (*alvar*) to SSH in using the same SSH key that worked before for root.
- Verified the new user's home directory with *ls -a -F -l /home/alvar/*
  - Ownership shows alvar alvar. That means the home directory and files belong now to the new user.

![Sieppaa31](https://github.com/user-attachments/assets/25230fe4-a7d3-4461-b9d6-052e86b0ca03)

- Then I have to change the permissions of those files still owned by root (because we copied files from root into /home/alvar/ earlier). We run *sudo chown -R alvar:alvar /home/alvar/*. Doing that we can avoid problems like SSH refusing to use *authorized_keys* and permission errors. Running this command I also ensure that *alvar* owns their home directory, the SSH key authentication works and other file permissions too.

![Sieppaa32](https://github.com/user-attachments/assets/c65488a1-14b0-4077-92c3-1ac65c9c4793)

- Now we lock the root account disabling root login, forcing the admin to work through *sudo*.

![Sieppaa33](https://github.com/user-attachments/assets/4c398dec-dfce-44f5-9e9d-c9224084bfe8)

- I changed the PermitRootLogin ensuring SSH root login is disabled with *sudoedit /etc/ssh/sshd_config > PermitRootLogin yes -> PermitRootLogin no*, saved and restarted.

  ![Sieppaa34](https://github.com/user-attachments/assets/db0b930a-8900-452c-99bb-09148ec4d995)
  ![Sieppaa35](https://github.com/user-attachments/assets/abab586b-dbcf-4ddb-9f64-f59757e48ac0)

- Next we set the firewall active
  - I check if SSH really stays on port 22 with *ss-tlnp | grep ssh* > Yes, it' s there:)
  - tryed to keep open the port 22 but says *ufw not found* > we have to install it first
  - So we run *sudo apt install ufw* (Firewalld is a firewall service daemon).
 
     ![Sieppaa36](https://github.com/user-attachments/assets/67963936-8a15-42dd-8856-04bdb54ef05d)
    
  - Finished installing we run *sudo ufw allow 22/tcp* -> we open this port because we don't want to be locked out when enabling UFW.
  - Then run *sudo ufw enable*. Now the firewall is on.
  
  ![Sieppaa37](https://github.com/user-attachments/assets/4269435c-22fb-4261-b5c6-13e0835a1e30)

- Now we upgrade packages to get latest security patches:
  - *$ sudo apt-get update*
  - *$ sudo apt-get upgrade*

  ![Sieppaa38](https://github.com/user-attachments/assets/9ae9e52a-32ef-4982-a8b6-3875f652a7ea)
